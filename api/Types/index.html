Types

The contracts VluxyAI is built from. You extend the package by passing in your own module that satisfies one of these types; the package never learns your module exists.

The important ones:

  • [Types.Brain]: a table of states. The part you write for every AI.
  • [Types.Pathfinder]: anything with FindPath. Plans, never moves.
  • [Types.Mover]: anything with Follow and Stop. Moves, never plans.
  • [Types.Sense]: anything with Tick that writes to the Types.Blackboard.
  • [Types.AgentDefinition]: the composition of the above, which Build() validates and turns into an Agent.

StepAction​

</>
type StepAction = "Walk" | "Jump" | "Custom"

What a Types.Mover does at a step. Mirrors Enum.PathWaypointAction. Custom steps come from PathfindingModifier labels or your own pathfinder; the mover walks to them like any other step and the Types.Navigator's StepReached tells you when it got there, so a door or a ladder is your code.

Step​

</>
interface Step {
Position: Vector3--

Where to go, as a floor position. Movers add their own height.

Action: StepAction--

What to do on the way there.

Label: string?--

The PathfindingModifier label, or whatever your pathfinder attaches. A Types.StepHandler registered for it runs when the step is reached.

Instance: Instance?--

What the step is about, when the pathfinder knows: the door on a Graph link.

}

One point along a Types.Path.

StepHandler​

</>
type StepHandler = (
agent: Agent,
step: Step,
index: number
) → (
boolean?,
number?
)

What happens at a labelled step: open the door, climb the ladder, play the vault. Registered with Builder:OnStep under the step's Label. Runs in its own thread and may yield; the navigator holds the mover at the step, reports Interacting, and walks the rest of the path when the handler returns. A new target or Stop while it runs abandons the path; the handler should check Agent:IsDestroyed after a long yield.

Return false to say the step could not be taken (a locked door). The path is given up as Failed, and the pathfinder is told to Close that step for the seconds given as the second return (default 10), so the next plan goes another way. Returning nothing or true means the step was taken.

StepRegistration​

</>
interface StepRegistration {
Handler: StepHandler
Tag: string?--

When the step arrives without an Instance (a navmesh link or modifier), the nearest instance carrying this CollectionService tag within Radius of the step is put in step.Instance before the handler runs.

Radius: number?--

Studs. Default 8.

}

What Builder:OnStep stores for a label: the handler, and how to find the door for a step that does not already know it. A plain Types.StepHandler is accepted wherever this is.

Path​

</>
type Path = {Step}

An ordered list of steps from where the agent was to where it wants to be. The first step is the agent's own position when the pathfinder includes it; movers cope either way.

Pathfinder​

</>
interface Pathfinder {
FindPath: (
self: any,
from: Vector3,
to: Vector3,
agent: Agent
) → (
Path?,
string?
)--

Returns a path, or nil and a reason. May yield.

Destroy: ((self: any) → ())?--

Optional cleanup. Called when the agent is destroyed.

Name: string?--

Used in messages, such as a Ladder's joined reasons.

Blocked: Signal<()>?--

Optional. Fired when the world changes under the last path returned; the Navigator re-plans on its cadence.

Close: ((
self: any,
step: Step,
seconds: number
) → ())?--

Optional. A labelled step could not be taken (a locked door): plan around it for seconds. Graph closes the link, Navmesh refuses paths through it; Ladder and Hybrid pass it on.

}

Plans and nothing else. A pathfinder never moves the agent, never creates parts and never keeps a target. from and to may be at any height: from is the mover's root and to is often a player's root or a floor node; the path it returns holds floor positions. An empty path counts as a failure. FindPath runs in its own thread and may yield or error; an error is treated as a failed plan and warned about once. VluxyAI.Pathfinders ships Navmesh, Straight and Ladder; your own is any table with FindPath.

Blocked is how a pathfinder that watches the world (Navmesh listens to its Path.Blocked) tells the navigator that the path being walked is no longer good, so the agent re-plans as soon as the cadence allows instead of walking into the obstacle and waiting for the mover's stuck check. A pathfinder that cannot know leaves it out; Ladder and Hybrid forward it from the rung that produced the current path.

Mover​

</>
interface Mover {
Follow: (
self: any,
path: Path
) → ()--

Starts moving along path, replacing any current path.

Stop: (self: any) → ()--

Halts. Fires Arrived(false) if a path was in progress.

GetPosition: (self: any) → Vector3--

Where the agent's root or pivot is right now: the body, not the floor.

GetSpeed: (self: any) → number--

Studs per second.

SetSpeed: (
self: any,
speed: number
) → ()--

Studs per second.

IsMoving: (self: any) → boolean--

true while a path is in progress.

StepReached: Signal<(
number,
Step
)>--

Fired with the index and step each time one is reached.

Arrived: Signal<boolean>--

Fired once per Follow: true at the end of the path, false if stopped, replaced or stuck.

Destroy: ((self: any) → ())?--

Optional cleanup. Called when the agent is destroyed.

Face: ((
self: any,
position: Vector3?
) → ())?--

Optional. Turn toward position while standing still; nil stops. Agent:LookAt calls it.

Teleport: ((
self: any,
position: Vector3
) → ())?--

Optional. Put the body at position at once, dropping any path. Agent:Teleport calls it.

SetNudge: ((
self: any,
offset: Vector3?
) → ())?--

Optional. Aim at each step plus offset (never the last step), so a steering sense can push the body sideways; nil clears. Neighbours calls it.

}

Executes a Types.Path and nothing else. Rules that keep a mover and the Navigator honest:

  • Follow fires Arrived(false) for the path it replaces before starting the new one, and the new path's outcome is reported on a later frame, never from inside Follow. An empty path is Arrived(false) on the next frame.
  • Follow is called from the navigator's planning thread, so it must not yield.
  • Arrived(true) means the last step was reached. The navigator then checks the target for itself: within ArriveDistance it reports arrival, otherwise it re-plans or reports failure.
  • Arrived(false) from a stuck detector makes the navigator re-plan on its cadence.

VluxyAI.Movers ships Humanoid (uses MoveTo) and CFrame (steps a pivot, no rig needed); your own is any table with this shape. Make the signals with VluxyAI.Signal.new().

Blackboard​

</>
type Blackboard = {[string]: any}

The only thing states read about the world. Senses write to it every tick; states and utility considerations read it and never query the world themselves. Each sense documents the keys it writes. Declare your own blackboard type per AI and cast once at the boundary.

Sense​

</>
interface Sense {
Tick: (
self: any,
agent: Agent,
deltaTime: number
) → ()--

Called once per agent tick. Writes to agent.Blackboard.

Destroy: ((
self: any,
agent: Agent?
) → ())?--

Optional cleanup, called with each agent that is destroyed. A shared sense releases that agent's state and tears down only when none remain; called with no agent it tears down outright.

Configure: ((
self: any,
patch: {[string]: any}
) → ())?--

Optional. Changes options after construction; every built-in has it, so a director can widen a cone or shorten a memory mid-round.

}

Perceives and nothing else. Senses tick in the order they were added, before the navigator and the brain. A sense keeps no per-agent state of its own: memory (SeenAt, HeardAt) lives on the blackboard, so one instance may serve many agents and a state may clear a memory early by setting the key to nil. Distances are math.huge when there is nothing to measure. VluxyAI.Senses ships Sight, Proximity, Hearing, Sounds, Awareness, Watched, Surroundings and Neighbours; your own is any table with Tick.

Transition​

</>
interface Transition {
To: string--

The state to enter. Must exist in the brain; Build() checks.

When: (agent: Agent) → boolean--

Checked every tick, in order, before Update.

}

A declarative transition. The first one whose When returns true wins. To may name the current state, which re-enters it (Exit then Enter); an Update returning the current name does nothing. If When forces a change through Agent:SetState, that change wins and its own result is ignored.

Interrupt​

</>
interface Interrupt {
To: string--

The state to enter. Must exist in the brain; Build() checks.

When: (agent: Agent) → boolean--

Checked every tick, in order, before the current state's own transitions.

Except: {string}?--

States in which this interrupt is not checked, such as the one it leads to or an attack that must finish.

}

A Types.Transition that applies from every state: "hunt whoever I see", "freeze when lit", "stop when the director says so". Written once on the brain instead of in every state. Interrupts are checked in order before the current state's transitions; the first true one wins the tick.

State​

</>
interface State {
Enter: ((agent: Agent) → ())?--

Runs once when the state becomes current.

Update: ((
agent: Agent,
deltaTime: number
) → string?)?--

Runs every tick. Return a state name to change state, or nothing to stay.

Exit: ((agent: Agent) → ())?--

Runs once when the state stops being current.

Transitions: {Transition}?--

Checked in order before Update each tick.

}

One state of a Types.Brain. Every field is optional, so a state can be as small as a single Update. Returning the current state's name from Update does nothing; use Agent:SetState to re-enter a state on purpose. If Update itself forces a change through SetState, its return value is ignored so two transitions never stack.

interface Brain {

Transitions that apply from every state, checked before the current state's own.

}

A flat finite state machine as a table. The whole AI, readable top to bottom.

PathStatus​

</>
type PathStatus = "Idle" | "Planning" | "Moving" | "Interacting" | "Arrived" | "Failed"

Where a Navigator is with its current target. Idle means no target or stopped; Interacting means a Types.StepHandler is running at a step and the walk resumes after.

NavigationOptions​

</>
interface NavigationOptions {
RepathInterval: number?--

Seconds between re-plans while the target keeps moving. Must be above 0; the three distances below may be 0. Default 0.5.

RepathDistance: number?--

Studs the target must move before a re-plan happens. Default 2.

MaxPathAge: number?--

Seconds a path is followed before it is planned again even though the target has not moved, so the agent keeps up with a changing level. Must be above 0. Default math.huge (never).

ArriveDistance: number?--

Horizontal studs from the target that count as arrived. Must exceed the two bodies' radii for a chase to ever arrive. Default 2.5.

ArriveHeight: number?--

Height difference allowed for arrival, so a target on the floor above does not count. Default 8.

}

Tunes how Navigator turns repeated MoveTo calls into plans.

Navigator​

</>
interface Navigator {
MoveTo: (
self: any,
target: Vector3
) → ()--

Head to target. Safe to call every tick; re-plans on a cadence.

Stop: (self: any) → ()--

Forget the target and halt.

GetStatus: (self: any) → PathStatus--

Where the navigator is with its target.

GetTarget: (self: any) → Vector3?--

The current target.

GetPath: (self: any) → Path?--

The last path planned.

StepReached: Signal<(
number,
Step
)>--

Forwarded from the mover.

Arrived: Signal<boolean>--

Fired when the target is reached (true) or given up on (false).

PathChanged: Signal<Path?>--

Fired with each new path, and with nil when there is none.

}

Owns the pair of a Types.Pathfinder and a [Types.Mover]: plans with one, follows with the other, and re-plans when the target moves, the pathfinder reports the path blocked, or the path is older than MaxPathAge. Every agent with both has one at agent.Navigator.
