Replica

The client side of an enemy: a rig, a table of client states, and three inputs the game's remote handlers call. Runs on the client; the package is shared realm so it is there. 

local replica = VluxyAI.Sync.Replica.new({
	Entity = model,
	Visuals = {
		Hunt = {
			Enter = function(replica) replica.Data.Highlight.Enabled = true end,
			Exit = function(replica) replica.Data.Highlight.Enabled = false end,
		},
	},
})
replica:On("Kill", function(payload) ... end)

syncRemote.OnClientEvent:Connect(function(message)
	if message.Kind == "State" then replica:SetState(message.State)
	elseif message.Kind == "Position" then replica:SetPosition(message.Position, message.Yaw)
	elseif message.Kind == "Event" then replica:Receive(message.Name, message.Payload) end
end)

interface ReplicaOptions {
Entity: PVInstance--

The rig, or anything with GetPivot and PivotTo.

Visuals: Visuals?--

Client states keyed by server state name. Missing states are fine.

Puppet: boolean?--

true to move the rig toward streamed positions. Default false.

Smoothing: number?--

Studs per second of catch-up in puppet mode; 0 snaps. Default 24.

TurnSmoothing: number?--

Radians per second of turning in puppet mode; 0 snaps. Default 12.

HeightOffset: number?--

Added to streamed positions, for a client rig whose pivot sits higher than the server's. Default 0.

}

SetState​

</>
Replica.SetState(
self: ReplicaClass,
name: string--

The server state's name.

) → ()

Runs the current visual state's Exit, then the new one's Enter, and fires StateChanged. A state with no visuals is tracked all the same. Setting the current state again re-enters it. A SetState made from inside Exit does not run that Exit again; an Exit or Enter that errors is warned about and the state still moves on.
